Vec

PETSc vectors (Vec) are the fundamental building blocks for storing solution data, right-hand sides, and other distributed arrays. PETSc.jl provides a Julia-friendly interface that makes Vec objects behave like native Julia arrays.

Overview

PETSc vectors support:

  • Distributed parallel storage: Split across MPI processes
  • Sequential storage: For serial computations
  • Ghost points: For communication in stencil operations
  • Julia array interface: a PetscVec is an AbstractVector, with bulk indexing, broadcasting and reductions

Example

julia> using PETSc, LinearAlgebra

julia> petsclib = PETSc.petsclibs[1];

julia> PETSc.initialize(petsclib)

julia> v = PetscVec(petsclib, [1.0, 2.0, 3.0]);

julia> w = 2 .* v;

julia> dot(v, w)
28.0

julia> w[:]
3-element Vector{Float64}:
 2.0
 4.0
 6.0

julia> PETSc.destroy!(w); PETSc.destroy!(v);

Creating Vectors

Sequential Vectors

# Create a sequential vector of length n
v = PetscVec(petsclib, n)

# Wrap an existing Julia array (no copy)
julia_array = zeros(100)
v = PetscVec(petsclib, julia_array)

# `destroy!` releases it; a vector on MPI.COMM_SELF also gets a finalizer
PETSc.destroy!(v)

From DM Objects

# Create global and local vectors from a DM
gvec = PETSc.global_vec(dm)
lvec = PETSc.local_vec(dm)

PetscVec replaces v0.4's VecSeq and as_petsc_vec: construction goes through the type (naming conventions, §6).

Julia Array Interface

A PetscVec is an AbstractVector of the library's scalar type, so eltype, size, length, axes and the generic AbstractVector methods work as for any vector:

v[1:3] = [1.0, 2.0, 3.0]   # set a range (then assemble!)
v[2]                       # one entry
a = v[1:3]                 # a range, as a Vector
length(v)                  # global length, an Int
size(v)                    # (length(v),)
collect(v)                 # every entry, as a Vector

v[i] and v[i] = x are one C call each and reach only the entries owned by this rank; PETSc raises an error for any other. So on one rank a vector behaves like a Vector, and on several ranks code that touches only its own entries works. A loop over every entry is correct but slow, since each step is a C call: use with_local_array! for the entries each rank owns, which hands you a plain Julia array.

PETSc.with_local_array!(v) do a
    a[1] = 1.0
end

Reductions are collective and give every rank the global answer. sum, maximum, minimum, dot, norm and isapprox call PETSc directly. any, all, count and mapreduce (so sum(f, v), prod, extrema and reduce) run the function on the entries each rank owns and combine the results. collect(v), Vector(v) and copyto!(::Vector, v) give every rank the whole vector, so every rank must call them, and each needs memory for all length(v) entries. v == w compares the entries, also collectively. hash(v) throws, so key a Dict of vectors with an IdDict.

Linear Algebra

The vector operations of LinearAlgebra and the arithmetic operators call PETSc directly. All of them are collective, so every rank must make the call:

using LinearAlgebra

w = copy(v)            # VecDuplicate + VecCopy
dot(x, y)              # xᴴy, the global result on every rank
axpy!(α, x, y)         # y = αx + y
axpby!(α, x, β, y)     # y = αx + βy
rmul!(v, α)            # v = αv
z = x + y              # a new vector; so are x - y, -x, α * x and x / α

copy and the operators return a new PetscVec with the layout of their first vector argument. On more than one rank it has no finalizer, so call destroy! on it on every rank. Broadcasting follows the same rule: y .= α .* x .+ y updates y in place, and an out-of-place broadcast such as 2 .* x returns a new PetscVec with the layout of the first PetscVec in the expression. Both run on the entries each rank owns and work on any number of ranks. A broadcast whose entries are not numbers (x .> 0 gives Bool) throws, since a PetscVec holds only the library's scalar type: broadcast over x[:] for those.

Assembly

After setting values, vectors must be assembled:

v[1:2] = [1.0, 2.0]
PETSc.assemble!(v)  # Finalize vector assembly

v[i] = x and v[r] = vals only queue the values: call assemble! before a read or a reduction (norm, dot, sum) that must see them. This holds for a PetscVec(petsclib, comm, n) even on one rank, since it is an MPI-type Vec there.

Ghost Point Updates

For vectors with ghost points (from DMDA/DMStag):

# Update ghost values from neighboring processes
PETSc.ghost_update!(vec; mode = PETSc.INSERT_VALUES, scatter = PETSc.SCATTER_FORWARD)

# Or use begin/end for non-blocking:
PETSc.ghost_update_begin!(vec; mode = PETSc.INSERT_VALUES, scatter = PETSc.SCATTER_FORWARD)
# ... do other work ...
PETSc.ghost_update_end!(vec; mode = PETSc.INSERT_VALUES, scatter = PETSc.SCATTER_FORWARD)

PETSc.LibPETSc.PetscVec — Method
PetscVec(petsclib, v::Vector)

A standard, sequentially-stored serial PETSc vector, wrapping the Julia vector v.

This reuses the array v as storage, and so v should not be resize!-ed or otherwise have its length modified while the PETSc object exists. For the same reason v must be a Vector of exactly the library's scalar type; anything else throws an ArgumentError. Convert other arrays first: PetscVec(petsclib, Vector{PetscScalar}(w)). The vector keeps v alive, so PetscVec(petsclib, [1.0, 2.0]) is safe.

This should only be need to be called for more advanced uses, for most simple usecases, users should be able to pass Vectors directly and have the wrapping performed automatically

PETSc.ownership_range — Method
ownership_range(vec::AbstractPetscVec)

The range of indices owned by this processor, assuming that the vec is laid out with the first n1 elements on the first processor, next n2 elements on the second, etc. For certain parallel layouts this range may not be well defined.

The range is 1-based, always: an index into Julia data is 1-based (docs/src/man/naming.md §12.1).

Note

unlike the C function, the range returned is inclusive (idx_first:idx_last)

similar(v::AbstractPetscVec)

A new vector with the same layout as v (size, parallel distribution, type), its entries not set. similar(v, T) with T = eltype(v) gives the same. PETSc.acquire_local_array — Method
acquire_local_array(vec; read, write, memtype = :native) -> (arr, cpu_arr, backend)

Get the local array from vec without registering a Julia finalizer. Returns the user-visible array, the raw PETSc cpuarr needed for restore, and the backend tag that [`releaselocal_array`](@ref) takes.

With memtype = :native the array is where the Vec keeps its data, through VecGetArray*AndMemType. Extensions overload make_local_array(cpu_arr, backend) to wrap the raw array for their device (e.g. CUDAMemBackend → CuArray). With memtype = :host, or while no GPU extension is loaded, it is the host array of VecGetArray*, for any Vec type: for a device Vec PETSc copies the data to the host, and back to the device when it next needs it there after a write.

PETSc.memtype — Method
memtype(vecs::AbstractPetscVec...)

Query the PetscMemType of each Vec and return the corresponding array type. Errors if the Vecs are on heterogeneous devices (different PetscMemType values), since a single with_local_array! call cannot handle mixed backends. PETSc.with_local_array! — Method
with_local_array!(
    f!,
    vecs::NTuple{N, AbstractVec};
    read::Union{Bool, NTuple{N, Bool}} = true,
    write::Union{Bool, NTuple{N, Bool}} = true,
    memtype::Symbol = :native,
)
with_local_array!(f!, ::Type{A}, vecs...; read, write, memtype) where {A <: AbstractArray}

Apply f! to local array views of vecs.

With memtype = :native each array is where its Vec keeps the data: a device array for a Vec on a GPU, with the GPU package loaded. memtype = :host gives host arrays for every Vec, so host code runs on device Vecs; each such checkout of a device Vec copies its data to the host. Without a GPU package loaded, :native gives host arrays too, so the type follows what is loaded in the session: code that must stay on the host whatever else is loaded passes memtype = :host.

The optional ::Type{A} second argument (after the do-block function) asserts that every array returned from VecGetArray*AndMemType is of type A. Use it with do-block syntax:

with_local_array!(Vector, petsc_x; write=true) do x
    x .= 1
end

PETSc.with_local_arrays! — Method
with_local_arrays!(f!, g_fx::AbstractPetscVec, l_x::AbstractPetscVec; memtype = :native)

Call f!(fx, lx) with the local array of g_fx (written) and of l_x (read), as arrays a compute kernel can use, and hand both back to PETSc afterwards, also when f! throws. Returns what f! returns.

Where each array lives is decided for the pair: with a GPU backend extension loaded and both Vecs on the device, fx and lx wrap the device memory. When g_fx is on the host, fx is a device scratch array whose contents are copied back into g_fx on return, so the kernel can run on the device either way. Without a GPU extension loaded, or with memtype = :host, both are host arrays, also for device Vecs, whose data PETSc then copies to the host.

with_local_arrays!(g_fx, l_x) do fx, lx
    residual_kernel!(fx, lx)
end

ghost_update!(vec::AbstractPetscVec; mode = INSERT_VALUES, scatter = SCATTER_FORWARD)

Update the ghost values of vec and return it: ghost_update_begin! followed by ghost_update_end!. Use the two halves separately to overlap the communication with other work.

Base.isapprox — Method
isapprox(v::AbstractPetscVec, w::AbstractPetscVec; atol = 0, rtol, nans = false, norm = norm)

Whether v ≈ w as for Julia arrays: ‖v − w‖ ≤ max(atol, rtol·max(‖v‖, ‖w‖)), where rtol defaults to √eps of the real type when atol is zero. Collective: every rank gets the same answer. If ‖v − w‖ is not finite, because of an Inf or NaN entry, the entries are compared one by one, as Base does, and nans = true counts two NaNs as equal.

source
Base.mapreduce — Method
mapreduce(f, op, v::AbstractPetscVec; [init])

mapreduce over all entries of v, collective: each rank reduces the entries it owns and the partial results are combined in rank order, so every rank gets the same answer, also for an op that is not commutative. This is what sum(f, v), prod(v), extrema(v) and reduce(op, v) call. The results of f must be isbits. init is applied once, to the combined result.
